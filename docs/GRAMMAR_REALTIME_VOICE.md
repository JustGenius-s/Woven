# 文法阅读页实时语音伴读

文法阅读页右上角、原课文播放按钮右侧的“语音伴读”按钮，直接发起实时通话，不自动打开对话面板。连接中及通话中，入口沿右侧展开为竖向悬浮胶囊，提供三个按钮：静音/恢复麦克风、打开对话面板、挂断（连接中为取消连接）。面板与连接分别管理，收起后回到悬浮控制，继续通话。

通话胶囊由原生 `bindPopup` 承载，直接通过 `CustomPopupOptions.systemMaterial` 使用不额外赋色的 ULTRA_THIN 材质，保留系统折射、阴影与触摸光感。普通页面 Stack 不在 ArkUI 沉浸材质的生效区域，不能靠设置通用属性或增加透明底色获得折射。Popup 无箭头、无页面遮罩、不自动消失，固定对齐入口右边缘，间隔 12 vp；使用 250 ms 摩擦曲线淡入并轻移，内部三个按钮共享唯一材质背板。Popup builder 根节点保持正常布局，不设置 position、裁剪或第二层材质。入口本身保留普通模糊背板。

中间的对话按钮同时显示 AI 输出状态：收到回复文本/音频时显示“生成中”，本地音频队列播放期间显示五根持续起伏的波形柱及“讲解中”，播放结束回到“对话”。波形由原生 Animator 以 960 ms 周期、30 fps 驱动，通过纵向缩放保持按钮布局稳定；它表示输出活动，不表示麦克风音量。生成状态通过会话快照传递，播放状态来自音频服务；麦克风静音不遮盖 AI 输出提示。服务端音频结束后，本地待播音频仍显示讲解状态，迟到的最终字幕不重新点亮生成状态。仅在 Popup 实际可见时运行波形，浮窗隐藏、打开面板或组件销毁时取消动画，重新显示时恢复。

旁边的课文/原声播放条也由原生 Popup 承载相同材质，覆盖文法页和普通阅读页。展开宽度随阅读页变化，左右各留 16 vp，不再限制 360 vp 或为通话按钮缩窄；文法页仅将折叠入口向左移 56 vp，展开浮层的锚点仍对齐页面右侧留白。保留播放、暂停、前后切换、进度拖动和音轨列表；收起或点外部仅关闭播放条，不暂停音频。开始通话或打开通话面板时收起播放条。打开音轨列表或阅读设置 sheet 时隐藏播放条，避免遮住面板。Popup 消失时释放拖动状态，并忽略关闭后迟到的 Slider 结束事件；折叠入口仅绘制已播进度弧，不增加第二圈边框。

底部页面进度条共用 `ReaderPageProgress`，也通过原生 Popup 的 `systemMaterial` 获得超薄沉浸材质；页面内只保留底部布局锚点，Popup 内容根节点不再设置通用材质、背景色、裁剪或定位。保持两侧至少 16 vp、最大宽度 640 vp 和底部安全距离，使用 220 ms 摩擦曲线淡入并轻移。Slider 单独开启系统材质，使用原生滑块尺寸和样式，取消原先固定 10 vp 黑色圆点。没有页面或仅一页时保留不可拖动的进度显示。原生材质不支持或关闭时沿用公共的可读模糊背景回退。进度浮层无遮罩、不抢焦点，外部触摸继续交给阅读页，系统返回沿用阅读页退出动作。设置、目录、音轨及通话面板展示期间隐藏进度条，收起动画完成后恢复；隐藏、尺寸/页数变化或销毁时取消拖动，迟到的结束事件不提交跳页。进度展示与通话连接分别管理。

所有 sheet（含设置中的三个服务、阅读目录/设置、课文音频、添加视频、五十音及通话面板）统一调用 `appSheetOptions`，使用原生弹窗默认档 ULTRA_THICK、28 vp 圆角和同一深浅色遮罩，减弱背景透出与折射干扰；不再使用浮动工具栏的超薄档或自定义材质染色。原生材质路径不覆盖背景色、背景模糊；不支持材质时统一回退。通话 sheet 与 Popup 绑定在同一页面宿主上，打开面板或音轨 sheet 时隐藏 Popup，对话面板收起动画结束后才恢复，期间不重建连接或清空字幕。浮层外触摸穿透到 PDF，系统返回沿用阅读页退出行为。

## 使用

1. 从[新版语音 API Key 管理](https://console.volcengine.com/speech/new/setting/apikeys?projectName=default)获取密钥，填入应用“设置 → 实时语音 → 火山引擎”。只需要 API Key，不需要 APP ID。此前保存的新版语音 API Key 会继续使用；不再依赖 DeepSeek、离线识别或播客服务。
2. 打开一课 PDF，点右上角语音按钮，允许麦克风后直接连接，右侧显示悬浮控制。接通后的欢迎语为固定提示，可直接说“讲解这一页”或提问。回应根据教材由模型生成，不预先生成双人播客。缺少 API Key 时直接进入实时语音设置。
3. 可以直接插话，或进入面板点“打断”停止当前回应；悬浮控制和面板均可静音/恢复麦克风。面板显示双方的流式字幕。点向下箭头、滑下或返回关闭面板，通话与静音状态保持不变；再次打开沿用原连接与字幕。
4. 同一份 PDF 内翻页保持通话、正在播放的讲解、字幕和静音状态；后续提问按最新页讲解。快速翻页合并后同步最后停留的页面，不重复打招呼或自动发起新讲解。悬浮控制或面板中的“挂断”、更换 PDF、离开阅读页、打开设置或切到后台会结束通话。再次接通会重新带入当前页的教材信息。原课文音频与通话互斥。连接失败时，收起状态通过即时提示反馈，不自动弹出面板。

设置页只需填写 API Key，保存后直接发起连接。应用不增加手动开通步骤，也不引导用户寻找开通按钮；如果连接失败，按接口实际返回的错误排查。

- [鸿蒙 7 组件适配沉浸光感](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/arkts-immersive-light-sense-component-adaptation)：悬浮控制采用 ULTRA_THIN，sheet 按弹窗用途采用 ULTRA_THICK，并由公共配置统一管理。
- [开启沉浸光感](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/arkts-immersive-light-sense-enable)：除弹窗、Slider、Toggle 等列出的组件外，材质只在 Navigation/NavDestination 标题栏、底部 TabBar 等指定区域生效。通话浮窗必须通过 Popup 的 options 配置材质。
- [端到端实时语音·全双工版本](https://docs.volcengine.com/docs/6561/2549778?lang=zh)，核对的官方文档更新时间为 2026-09-04。
- [接入必读](https://docs.volcengine.com/docs/6561/2549732?lang=zh)，包括 PCM、静音保活、上下文、关闭确认和错误处理。
- 端点：`wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`；请求头仅 `X-Api-Key`。
- `session.create` 使用模型 `1.2.6.1`，音色 Vivi 2.0 `zh_female_vv_uranus_bigtts`。[官方音色列表](https://docs.volcengine.com/docs/6561/1257544?lang=zh#e7951cad)将其列为 S2S 全双工主打音色，明确标注中文、日文等语种；旧版 `zh_female_vv_jupiter_bigtts` 只标注中文。模型和音色使用公共常量，提示词里的会话音色也引用同一常量。教材讲解默认使用普通话，日语词句保留原文并按日语读音朗读；用户要求日语对话后，后续轮次沿用日语，直到用户要求切回中文。此处依据音色输出能力选择，不据此推断日语语音识别或口语评分能力。
- 创建与更新通话共用固定输出配置：Vivi 2.0、正常语速 `speed: 0`、默认音量 `loudness: 0`，并参照官方 Python 示例在顶层 `extension.dialog.extra` 开启 `enable_loudness_norm`。该参数均衡输出响度，不能保证生成式语音的音高、韵律完全一致。音色字段已与官方示例核对，应用没有随机选择或静默切换音色的逻辑。2026-09-07 用户再次确认，要求朗读日语或用日语回答时，AI 仍偶发说出“当前音色不支持回复”。本次移除围绕音色拒答的否定指令及固定音高约束，改为明确的中日双语角色、已配置音色的语言能力，以及日语朗读、日语解释、切回中文的正向示例。示例明确标记为语言用法，不作为教材内容或真实历史插入。该修改针对提示词干扰的可能性，尚未证明具体成因或消除模型侧拒答。真实接口错误仍正常显示和处理，不过滤语音或字幕，也不自动重连或重试回复。
- `KotobaRealtime` 日志记录请求的模型、音色、指令版本 `bilingual-2026-09-07`，以及服务端返回的 `X-Tt-Logid`、会话 ID、回复 ID、音频来源 `tts_type`。创建/更新确认如果提供模型和音色就记录其返回值，否则明确为 `unavailable`，不把客户端请求值冒充服务端确认。仅记录字符和长度受限的标识、允许的音频来源及数字错误码；不记录原始报文、请求头、密钥、PDF 文字、对话正文或音频。此信息用于后续区分普通生成与其他服务端音频来源，日志分类本身不证明拒答原因。
- 输入 `session.audio.input.format = { type: 'pcm', rate: 16000 }`：单声道 / 16 bit LE，每 20 ms 发送 640 字节。输出直接设置 `session.audio.output.format = { type: 'pcm_s16le', rate: 24000 }`，与本地 AudioRenderer 的单声道 S16LE 匹配。依据全双工文档附件 Python 示例的 `config.py`、`realtime_client.py` 和 `main.py`：默认 `tts_format` 为 `pcm_s16le`，写入会话输出字段，并使用 `paInt16` 播放；输出选择 `pcm` 时示例使用 `paFloat32`。不能把输入的 `pcm` 原样用于 16 位输出，也不能依赖扩展字段覆盖错误的会话输出类型。输入与输出的类型声明分别限定格式和采样率，避免再次混用。
- 播放前检查每轮输出的首部，跨分片拼接检查 OGG/WAV 标识；若返回封装音频，停止连接并提示格式错误，不将压缩数据当作 PCM 播放。裸 PCM 本身没有格式头，位深依靠上述明确配置。合法样本按原顺序排入缓冲区，打断时同时清空首部检查和播放缓冲。
- 下行播放先积累约 80 ms 音频，再连续送入 AudioRenderer；发生欠载时重新缓冲，避免每个网络分片都紧接一次静音。仅在播放开始、欠载停止/恢复和响应尾部施加 5 ms 的幅度渐变，正常连续播放段不滤波、不改变音量或样本顺序。收到音频结束事件后立即允许短响应和尾部排空；原生缓冲剩余空间写零，始终保持 PCM16 样本边界。此处理会增加约 80 ms 的启动缓冲，实际等待时间取决于分片到达时间。
- 启动缓冲与待播容量分别管理：待播音频最多 120 秒（5.76 MB PCM），允许模型合成速度快于实时播放。达到上限时取消当前回复、清空待播音频并提示继续提问，保持会话、麦克风与字幕；取消确认后可以继续接收新回复。此容量只计算尚未播放的音频，不限制通话总时长。音频仅保存在内存中。
- PCM16 样本可以跨网络分片，孤立的半个样本保留到下一片拼接，打断时清除；仅在音频结束事件到达后仍缺少另一个字节时报告数据不完整。Base64 解码错误单独提示，不与缓冲达到上限混为“内容异常”。
- 全部事件都是 JSON 文本帧，音频为 Base64。持续上行使用 `input_audio_buffer.append`。静音/恢复发送 `input_audio_mute.commit` / `input_audio_unmute.commit`。
- 同一 PDF 翻页通过 `session.update` 替换教材 instructions，等待 `session.updated` 确认后再发送后续页面更新；沿用原连接、模型和音频配置，明确保留 PCM16 与日语音色。翻页不发送 `response.cancel`、`session.close` 或欢迎语，也不清空本地待播音频。页码与连接分别管理版本，连续翻页先合并 200 ms，并丢弃已过期的读取结果；读取教材、等待麦克风权限或建立连接期间翻页，也会在接通时补齐最新页。挂断后迟到的读取和更新结果不能恢复旧会话。
- `response.cancel` 同时清空本地待播音频与原生缓冲，忽略已打断 response ID 的后续音频。等待 `response.canceled` 确认；超时结束连接。
- 结束时先发送 `session.close`，收到 `session.closed` 后关闭 WebSocket；网络失联时最多等待 1.5 秒。异常不自动重新打开麦克风，用户可主动再连接。
- HarmonyOS 配对使用 `SOURCE_TYPE_VOICE_COMMUNICATION` 采集与 `STREAM_USAGE_VOICE_COMMUNICATION` 播放，使平台启用通话的 3A 处理。回声消除、路由、实际延迟仍须真机验证。

## 教材与数据

PDFKit 提取本地 PDF 文字，优先当前页，并带有明确 PDF 页码的邻页和教材摘录。参考内容最多 10,000 字符写入会话 instructions；不把 PDF 中的命令当作系统指令。开始通话时，纯扫描页没有可提取文字会给出提示；通话中翻到空白页或扫描页则保持连接，明确告知模型该页没有可读文字，不能沿用上一页冒充当前页。单页读取失败同样提示并更新为内容不可用，不中断通话。当前实现不发送页面图片。

仅主动点击阅读页语音入口或面板中的“开始语音对话”后申请麦克风权限和连接服务。接通后，麦克风声音及教材文字会发送至火山服务。收起面板后仍保持通话；静音停止麦克风采集，挂断释放采集与网络连接。密钥保存在本设备已有私有配置存储，不进入学习数据同步。应用不保存通话录音或会话 ID；字幕仅在当前阅读组件内保留，服务端保留规则以火山为准。错误提示不显示服务端原始请求或密钥。

## 验证范围

双语指令调整使用内存中的模拟 WebSocket 检查，确认创建、连续翻页更新和重新连接均发送同一 Vivi 2.0、PCM16、语速、音量及响度均衡配置；日语字幕、拒答原文和真实服务错误仍正常呈现，诊断信息不会泄露测试密钥、教材或对话正文。翻页合并、更新确认、读取失败、连接期间翻页和挂断竞态检查通过。构建通过，未调用真实模型或进行设备试听，因此不据此断言偶发语言拒绝或声线变化已消失。

进度条材质调整经过构建和内存逻辑检查：材质支持/流畅/关闭/不支持分支、页码范围、拖动完成跳页、取消后迟到事件、外部触摸及返回处理。没有操作模拟器或手机，原生折射、位置和多浮层视觉效果由用户验收。

翻页修复在内存中运行实际会话、WebSocket 协议和教材组装代码，替换网络与原生音频边界：覆盖讲解中翻页保持音频、字幕和静音，快速翻页合并，等待更新确认时继续翻页，旧读取结果隔离，读取教材/准备麦克风/连接期间翻页，以及空白页、单页读取失败、更换 PDF、后台退出和挂断后重连。另验证更新确认超时与发送失败释放请求、计时器和音频资源。未调用真实服务或操作模拟器，真机连续通话与讲解内容由用户确认。

开发期间的本地检查运行实际 ArkTS 服务代码，替换原生和网络边界，覆盖官方消息格式、API Key 复用、PCM 分包节奏与缓存、静音、打断后的延迟音频、结束确认、权限取消、晚到设备创建、后台退出与翻页上下文隔离。额外执行阅读控件的实际生命周期和动作方法，检查直接发起连接、重复点击、收起/重开不重连、继续传输音频、保留静音、显式挂断、浮层失败提示、设置跳转以及连接中取消，并验证原课文播放与页面导航边界。临时脚本已按要求清理，不随功能代码提交。声明式布局由 ArkUI 编译器检查，视觉和手势由用户验证。

音频格式修复使用内存中的模拟原生/网络边界检查：确认实际创建请求的 `session.audio.output.format.type` 为 `pcm_s16le`，与播放器参数一致；确认已知波形经过分片后逐字节不变、缓冲尾部补零、极短响应尾部、打断后首部重置，以及跨分片 OGG/WAV 和后续响应格式拦截。没有新增仓库内的测试脚本。此前只在扩展字段指定 PCM16 的版本，经用户试听仍有重杂音；本轮依据官方示例修正会话输出字段，实际听感仍由用户确认。

用户确认 PCM16 格式修正后清晰度改善，但静音后仍有持续沙沙声，使用环境为模拟器经电脑外放。随后对播放缓冲作了独立检查：模拟 60 ms 音频批次出现 40 ms 交替延迟时，旧实现出现 2 个中途静音块，相邻样本最大跳变为 8608；增加缓冲和边界渐变后，中途静音块为 0，最大跳变为 628。90 ms 大分片与 1024 字节原生缓冲组合也没有中途静音块。另检查正常连续段除首尾 5 ms 外逐字节一致、长时间欠载重新缓冲、短句排空、静音填充、打断重置、原生缓冲样本对齐，以及实际 Duplex 服务在静音和异步 flush 下的输出。上述检查证明分片断点问题改善，不能代替实际听感，也不能据此认定持续沙沙声完全来自分片或模拟器。
