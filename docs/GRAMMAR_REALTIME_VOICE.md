# 文法阅读页实时语音伴读

文法阅读页右上角、原课文播放按钮右侧的“语音伴读”按钮，直接发起实时通话，不自动打开对话面板。连接中及通话中，入口沿右侧展开为竖向悬浮胶囊，提供三个按钮：静音/恢复麦克风、打开对话面板、挂断（连接中为取消连接）。面板与连接分别管理，收起后回到悬浮控制，继续通话。

按钮与面板使用现有最薄透明材质 `FLOATING_ULTRA_THIN_MATERIAL`。悬浮胶囊使用一个持续存在的材质容器，250 ms 摩擦曲线同步改变位置、尺寸与圆角，内部图标错时淡入淡出；不叠加第二圈边框或多层材质。点击面板按钮才拉起原生 sheet，面板使用系统展开、收起动效；不显式覆盖 sheet 的背景色，以免屏蔽原生沉浸材质。浮层外的触摸穿透到 PDF。

## 使用

1. 从[新版语音 API Key 管理](https://console.volcengine.com/speech/new/setting/apikeys?projectName=default)获取密钥，填入应用“设置 → 实时语音 → 火山引擎”。只需要 API Key，不需要 APP ID。此前保存的新版语音 API Key 会继续使用；不再依赖 DeepSeek、离线识别或播客服务。
2. 打开一课 PDF，点右上角语音按钮，允许麦克风后直接连接，右侧显示悬浮控制。接通后的欢迎语为固定提示，可直接说“讲解这一页”或提问。回应根据教材由模型生成，不预先生成双人播客。缺少 API Key 时直接进入实时语音设置。
3. 可以直接插话，或进入面板点“打断”停止当前回应；悬浮控制和面板均可静音/恢复麦克风。面板显示双方的流式字幕。点向下箭头、滑下或返回关闭面板，通话与静音状态保持不变；再次打开沿用原连接与字幕。
4. 悬浮控制或面板中的“挂断”结束连接并收回悬浮胶囊。翻页、离开阅读页、打开设置或切到后台仍会结束通话。再次接通会重新带入当前页的教材信息。原课文音频与通话互斥。连接失败时，收起状态通过即时提示反馈，不自动弹出面板。

设置页只需填写 API Key，保存后直接发起连接。应用不增加手动开通步骤，也不引导用户寻找开通按钮；如果连接失败，按接口实际返回的错误排查。

## 接入依据

- [鸿蒙转场动效设计指南](https://developer.huawei.com/consumer/cn/doc/design-guides/transition-animation-0000001750078488)：持续元素、共享容器、进出场元素的错时淡入淡出。
- [鸿蒙 7 组件适配沉浸光感](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/arkts-immersive-light-sense-component-adaptation)：薄材质与系统反色资源、限制材质面积和层数、sheet 使用原生系统材质。按本项目的透明度要求选择 ULTRA_THIN。
- [端到端实时语音·全双工版本](https://docs.volcengine.com/docs/6561/2549778?lang=zh)，核对的官方文档更新时间为 2026-09-04。
- [接入必读](https://docs.volcengine.com/docs/6561/2549732?lang=zh)，包括 PCM、静音保活、上下文、关闭确认和错误处理。
- 端点：`wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`；请求头仅 `X-Api-Key`。
- `session.create` 使用模型 `1.2.6.1`，音色 Vivi 2.0 `zh_female_vv_uranus_bigtts`。[官方音色列表](https://docs.volcengine.com/docs/6561/1257544?lang=zh#e7951cad)将其列为 S2S 全双工主打音色，明确标注中文、日文等语种；旧版 `zh_female_vv_jupiter_bigtts` 只标注中文。教材讲解使用中文，日语词句保留原文并按日语读音朗读，不以中文读汉字或用中文谐音替代假名。此处依据音色输出能力选择，不据此推断日语语音识别或口语评分能力。
- 输入 `session.audio.input.format = { type: 'pcm', rate: 16000 }`：单声道 / 16 bit LE，每 20 ms 发送 640 字节。输出直接设置 `session.audio.output.format = { type: 'pcm_s16le', rate: 24000 }`，与本地 AudioRenderer 的单声道 S16LE 匹配。依据全双工文档附件 Python 示例的 `config.py`、`realtime_client.py` 和 `main.py`：默认 `tts_format` 为 `pcm_s16le`，写入会话输出字段，并使用 `paInt16` 播放；输出选择 `pcm` 时示例使用 `paFloat32`。不能把输入的 `pcm` 原样用于 16 位输出，也不能依赖扩展字段覆盖错误的会话输出类型。输入与输出的类型声明分别限定格式和采样率，避免再次混用。
- 播放前检查每轮输出的首部，跨分片拼接检查 OGG/WAV 标识；若返回封装音频，停止连接并提示格式错误，不将压缩数据当作 PCM 播放。裸 PCM 本身没有格式头，位深依靠上述明确配置。合法样本按原顺序排入缓冲区，打断时同时清空首部检查和播放缓冲。
- 下行播放先积累约 80 ms 音频，再连续送入 AudioRenderer；发生欠载时重新缓冲，避免每个网络分片都紧接一次静音。仅在播放开始、欠载停止/恢复和响应尾部施加 5 ms 的幅度渐变，正常连续播放段不滤波、不改变音量或样本顺序。收到音频结束事件后立即允许短响应和尾部排空；原生缓冲剩余空间写零，始终保持 PCM16 样本边界。此处理会增加约 80 ms 的启动缓冲，实际等待时间取决于分片到达时间。
- 启动缓冲与待播容量分别管理：待播音频最多 120 秒（5.76 MB PCM），允许模型合成速度快于实时播放。达到上限时取消当前回复、清空待播音频并提示继续提问，保持会话、麦克风与字幕；取消确认后可以继续接收新回复。此容量只计算尚未播放的音频，不限制通话总时长。音频仅保存在内存中。
- PCM16 样本可以跨网络分片，孤立的半个样本保留到下一片拼接，打断时清除；仅在音频结束事件到达后仍缺少另一个字节时报告数据不完整。Base64 解码错误单独提示，不与缓冲达到上限混为“内容异常”。
- 全部事件都是 JSON 文本帧，音频为 Base64。持续上行使用 `input_audio_buffer.append`。静音/恢复发送 `input_audio_mute.commit` / `input_audio_unmute.commit`。
- `response.cancel` 同时清空本地待播音频与原生缓冲，忽略已打断 response ID 的后续音频。等待 `response.canceled` 确认；超时结束连接。
- 结束时先发送 `session.close`，收到 `session.closed` 后关闭 WebSocket；网络失联时最多等待 1.5 秒。异常不自动重新打开麦克风，用户可主动再连接。
- HarmonyOS 配对使用 `SOURCE_TYPE_VOICE_COMMUNICATION` 采集与 `STREAM_USAGE_VOICE_COMMUNICATION` 播放，使平台启用通话的 3A 处理。回声消除、路由、实际延迟仍须真机验证。

## 教材与数据

PDFKit 提取本地 PDF 文字，优先当前页，并带有明确 PDF 页码的邻页和教材摘录。参考内容最多 10,000 字符写入会话 instructions；不把 PDF 中的命令当作系统指令。纯扫描页没有可提取文字时给出提示，不凭空讲解图像。当前实现不发送页面图片。

仅主动点击阅读页语音入口或面板中的“开始语音对话”后申请麦克风权限和连接服务。接通后，麦克风声音及教材文字会发送至火山服务。收起面板后仍保持通话；静音停止麦克风采集，挂断释放采集与网络连接。密钥保存在本设备已有私有配置存储，不进入学习数据同步。应用不保存通话录音或会话 ID；字幕仅在当前阅读组件内保留，服务端保留规则以火山为准。错误提示不显示服务端原始请求或密钥。

## 验证范围

开发期间的本地检查运行实际 ArkTS 服务代码，替换原生和网络边界，覆盖官方消息格式、API Key 复用、PCM 分包节奏与缓存、静音、打断后的延迟音频、结束确认、权限取消、晚到设备创建、后台退出与翻页上下文隔离。额外执行阅读控件的实际生命周期和动作方法，检查直接发起连接、重复点击、收起/重开不重连、继续传输音频、保留静音、显式挂断、浮层失败提示、设置跳转以及连接中取消，并验证原课文播放与页面导航边界。临时脚本已按要求清理，不随功能代码提交。声明式布局由 ArkUI 编译器检查，视觉和手势由用户验证。

音频格式修复使用内存中的模拟原生/网络边界检查：确认实际创建请求的 `session.audio.output.format.type` 为 `pcm_s16le`，与播放器参数一致；确认已知波形经过分片后逐字节不变、缓冲尾部补零、极短响应尾部、打断后首部重置，以及跨分片 OGG/WAV 和后续响应格式拦截。没有新增仓库内的测试脚本。此前只在扩展字段指定 PCM16 的版本，经用户试听仍有重杂音；本轮依据官方示例修正会话输出字段，实际听感仍由用户确认。

用户确认 PCM16 格式修正后清晰度改善，但静音后仍有持续沙沙声，使用环境为模拟器经电脑外放。随后对播放缓冲作了独立检查：模拟 60 ms 音频批次出现 40 ms 交替延迟时，旧实现出现 2 个中途静音块，相邻样本最大跳变为 8608；增加缓冲和边界渐变后，中途静音块为 0，最大跳变为 628。90 ms 大分片与 1024 字节原生缓冲组合也没有中途静音块。另检查正常连续段除首尾 5 ms 外逐字节一致、长时间欠载重新缓冲、短句排空、静音填充、打断重置、原生缓冲样本对齐，以及实际 Duplex 服务在静音和异步 flush 下的输出。上述检查证明分片断点问题改善，不能代替实际听感，也不能据此认定持续沙沙声完全来自分片或模拟器。

本轮未调用真实模型、采集真实麦克风或操作模拟器。人工验证时重点检查右侧悬浮控制的位置与触摸范围、入口到胶囊的连续动效、面板收起后继续对话且静音状态不变、重新打开保留字幕、显式挂断/后台后系统麦克风指示消失，以及扬声器回声、蓝牙音频路由和插话延迟。

长回复回归检查在内存中运行实际服务代码：旧版 480,000 字节待播上限，在 2 倍实时速度生成时于 9.9 秒触发溢出并被统一报为内容异常。修复后 45 秒音频完整播放，峰值待播 22.6 秒；连续 10 段各 30 秒音频均排空。另验证 120 秒待播上限不继续分配音频缓存、超限只取消当前回复并保留连接/麦克风/字幕、丢弃被取消回复的迟到数据、新回复恢复播放，以及奇数字节分片逐样本重组、打断隔离、末尾残缺检测、跨分片容器拦截和解码失败的独立提示。未新增测试脚本或操作测试设备。
